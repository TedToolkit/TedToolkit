## 🧩 Explicit Governance Constraints

Combine depends on Build and keeps GitHub/GitLab SDKs inside internal providers. Its public API exposes no SDK type and depends on no Feishu or other notification SDK. `PipelineExecutionPolicy.Standard` selects `LocalBuild`, `Publish`, `Message`, or `None` from shared main/development and CI semantics. Manual policy can select any of the six profiles. Consumers choose same-process `RunBuild` or cross-job `ConsumeArtifacts`. Every remote and notification action in every profile requires its explicit switch; selecting `Message` never authorizes PR/MR mutation by itself.

## 🎯 Outcome, Scope, and Non-goals

The outcome is a library-level `TedToolkit.ModularPipelines.Combine` composition API, such as `AddStandardPipeline`, callable from a consumer `Program.cs`, plus migration of this repository's non-packable Build host as its first real consumer. Combine owns input-mode selection, manifest validation, module order, configuration validation, profile selection, provider selection, and neutral event dispatch. Consumers see only neutral models and `RepositoryProviderKind`, never provider SDK clients. The repository host directly project-references Build and Combine; package-only consumption remains a separate P2-NUPIPE-006 boundary.

Non-goals: no package-owned executable `Program.cs` with fixed configuration; no built-in Feishu, Slack, Teams, email, or concrete AI; no business-branch choice inferred from arbitrary environment variables; no provider packages that consumers must manage separately; no live external package push as implementation evidence or independent-consumer CI evidence. This work package does not enable `NUGET_RELEASE_ENABLED`; provider-owned GitHub mutation remains unavailable until P2-NUPIPE-004 passes.

## 🔍 Current Behavior and Impact Boundary

`TedPipeline.ExecuteAsync` registers a fixed module list, while `Build/Program.cs` manually composes the actual entry-point list. That list includes `NugetPushModule` but omits `BumpVersionModule`, `PublishModule`, and `CreateReleaseModule`; it is the compatibility baseline, while the broader unused graph is evidence only. The current GitHub workflow gives every trigger write permissions and passes AI, NuGet, and GitHub credentials to one Build step. Its implicit build-time package path can succeed with no package because the inspected projects do not import the solution-item `props/NugetPackage.props` and the actual graph has no reliable package producer before the push module. Explicit three-package production/publication and same-version GitHub Release creation are approved corrective outcomes, not legacy behavior claims. EverythingButTheSink Combine is a GitLab-specific executable. Neither approach is a configurable public library entry point or a least-privilege publication flow.
