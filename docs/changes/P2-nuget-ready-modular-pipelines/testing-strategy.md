## TDD Slice Order

Each work package loops through one failing minimal TUnit test, the corresponding Release run, the smallest implementation, and a rerun. Do not migrate a full source batch before tests.

1. P2-NUPIPE-001: analyzer disposition/license/dependency gate → exact Sonar dependency-activation PoC → package metadata and copied assets → local-source restore/build → `.editorconfig` diagnostic severity.
2. P2-NUPIPE-002: dependency-baseline PoC → models/root safety → resources → pure calendar policy → temporary version transaction/recovery → both test commands → failure/restoration DAG → pack/publish archives → exact manifest round trip → opt-in descriptions → dependency boundary.
3. P2-NUPIPE-003: neutral context resolver → profile/action/write matrix → input/failed-manifest gate → strict configuration → secret resolver/NuGet push → default-off package-checkpoint contract → change-request policy → rich results/events → provider-neutral Release finalizer contract → extension hook → actual `Build/Program.cs` ProjectReference/local parity → one-time release-history capture/acceptance → tag-based calendar version, SDK-visible stamping, exact restoration, and serialized workflow split → gated local package/progress/tag push against fake boundaries → failure ownership → optional adapter.
4. P2-NUPIPE-004: isolated client PoC → User-approved supplemental ADR → context/connection/URI/auth → no-op → PR/Release idempotency → revision → draft-first resumable hash-safe assets → empty-artifact Release finalization → API contract.
5. P2-NUPIPE-005: isolated client PoC → User-approved supplemental ADR → context/URL/prefix/auth → MR/Release idempotency → per-artifact names/revision → package-first resumable hash-safe Release → API contract.
6. P2-NUPIPE-006: local-source package-only fixtures with direct Build/Combine PackageReferences → YAML/static consumer-template contract → package release gate → accepted release-history hash/evidence gate → two-process EverythingButTheSink-derived compatibility fixture → optional-adapter fixture → side-effect-free real CI dry runs.

```powershell
dotnet run --project tests/TedToolkit.CodeAnalysis.PackageTests -c Release
dotnet run --project tests/TedToolkit.ModularPipelines.Build.Tests -c Release
dotnet run --project tests/TedToolkit.ModularPipelines.Combine.Tests -c Release
dotnet run --project tests/TedToolkit.ModularPipelines.Combine.GitHub.Tests -c Release
dotnet run --project tests/TedToolkit.ModularPipelines.Combine.GitLab.Tests -c Release
dotnet run --project tests/HostCompatibility/TedToolkitBuildHostCompatibility -c Release
dotnet run --project tests/ReleaseContract.Tests -c Release
```

Consumer fixture scripts run `dotnet restore` and `dotnet build` in independent processes. Package source mapping resolves `TedToolkit.*` only from the temporary candidate source and all other dependencies only from controlled upstream sources, then reports actual versions and sources. The Build-only host references only Build and calls `AddBuildPipeline`; a host that calls both APIs has direct same-version PackageReferences to Build and Combine.

`tests/HostCompatibility/TedToolkitBuildHostCompatibility` records the actual old `Build/Program.cs` host's effective non-secret inputs and command/output/exit semantics, then executes the migrated project-referenced host in isolated clean and controlled dirty workspaces. It simulates the two GitHub jobs through paginated capture data, valid/invalid pre-cutover baseline files, complete local tag history, deterministic caller-supplied dates representing TedToolkit's runner-local calendar, artifact copy/loss, a false/true release gate, a local NuGet endpoint, a local bare Git remote, and a recording GitHub Release boundary. It proves one-time baseline capture/acceptance evidence; runtime baseline/tag validation without a GitHub API call; neutral consumed-version mapping; date/highest-consumed-counter and package-success-rerun behavior; package-success and abandoned counters; active pending blocks every new build; checkpoint default-off/explicit registration, read-before-NuGet-secret, completed-ID filtering, record-between-push ordering, immutable package-progress validation, unmarked duplicate/uncertainty rejection, full-set completion exactly once before Provider publication, and completion-created package success even when every ID was read as completed; original-run artifact recovery, pre-package-success abandonment, post-package-success required-Release finalization with/without the original artifact through Combine's neutral finalizer, zero NuGet resolution in package-success recovery, and zero NuGet/provider resolution in abandoned cleanup; absence of a host GitHub SDK/API implementation; serialized workflow configuration; temporary `Directory.Build.props` stamping visible to pipeline-owned SDK commands; exact assembly/file/informational/package/manifest mapping; byte-identical success/failure/cancellation restoration; hash-safe interrupted-run recovery across every active profile and None zero-call behavior; outer bootstrap outputs excluded from the manifest; no staged/committed version difference; no NuGet credential in build/pack; no rebuild in publication; pending/package/progress/package-success/Release/abandoned-tag ordering; distinct Build-versus-publication failure ownership; and retained CI evidence. It never pushes externally or compares a credential value, and treats the approved three-package/Release correction, generated model text, exact logs, timing, removed failure-list/raw-output files, and unpack/re-zip intermediates as intentional non-contractual differences.

The EverythingButTheSink-derived fixture runs process A to build, test, pack, create named publish archives, and write the manifest; copies the artifact root to an isolated workspace; then runs process B with `ConsumeArtifacts`. Process B runs no build/test/pack/publish command and validates status, revision, paths, hashes, and sizes. `consumer-baselines.json` pins the approved source identifier/commit without an internal URL or machine path. The fixture re-expresses minimum semantic behavior and never accesses or modifies the external repository at runtime.

Before release readiness, copy the canonical `tests/Consumers/Templates/github-actions.yml` and `gitlab-ci.yml` bytes into the User-provided GitHub and GitLab test environments and run them with all remote switches disabled. GitLab Combine uses full history (`GIT_DEPTH: 0`); GitHub uses `fetch-depth: 0` whenever change descriptions, commit summaries, or calendar-version resolution are enabled. Retain the template SHA-256, run links, and sanitized logs showing candidate-package resolution, selected profile, artifact transfer, and zero mutations. These dry runs are manual release evidence, not TUnit entry points or production rollout.
